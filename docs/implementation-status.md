# LLD 实现进度（2026-09-22）

产品原则：球员 + AI + 真人教练协作，先补齐可使用的功能，再优化识别质量。此清单是当前仓库状态，不宣称全部 LLD 已完成。

## 已接通

- 视频分片上传、九阶段分析、状态查询、受保护媒体播放、报告证据、时间线修订和重算、片段/集锦导出。
- 私人发球候选审核、练习类型分类、quiz 观察/回放/练习历史；不提供未经核实的标准答案评分。
- 视频批量选择与删除；集成测试自动清理测试上传。
- 教练专属工作台：球员搜索、评审状态筛选、授权视频入口、训练反馈与复测总览。
- 球员/教练账号注册、逐视频授权和撤销、教练评审队列、区间批注与完成状态。
- 训练任务生成/手工制定、来源与版本、教练覆盖和锁定、球员反馈、复测条件检查和不可变结果历史。

## 仍需实现或补齐

- 上传会话跨刷新恢复、完整认证生命周期（refresh/revoke 等）。
- 删除回收站、保留期恢复与最终物理清理；当前仅软删除和清理任务占位。
- 管理员运维入口、重试/成本治理、完整审计与旧接口幂等覆盖。
- 其他用途 consent、数据治理及部署运维能力。
- 受证据约束的 LLM 报告叙述；当前是确定性指标与规则发现。
- 更完整的跨会话基线和面向技术训练的指标体系；当前复测只比较已有受支持指标。
- 教练对分析标签的正式裁决流程；本轮教练指导体现在批注和训练计划中。

### 功能优先的建议顺序

1. 上传恢复、认证会话、删除回收/恢复，让日常使用完整。
2. 教练正式标签确认、quiz 发布检查与确认答案，把人工指导落实到证据与练习内容。
3. 报告/指标缺项与多用途导出授权；LLM 接入时补齐证据校验和降级。
4. 队列可靠性、运维入口、CI 和生产部署验收。

感知管线中完全缺失的能力仍是功能缺口；已有分类器的人声鲁棒性、边界精度等才是明确后置的优化。Redis、GPU、多码率播放、教练语音反馈、tus 和公共题库属于 LLD §16 明确后置项，不计入本轮 P0 完成要求。仓库拆分按用户新决定执行，不要求回到 LLD 早期的单仓布局。

## 最新优先级修正

用户确认自动 labelling 仍是目标：综合触球前后动作、接球方式和球的后续表现作为推断证据，不把“教练手工填写答案”设为主流程。现阶段已有基本可用功能，转向当前训练视频的精度验证。上传恢复、会话和回收站后置。本轮先修击球计数（落台/噪声误计及边界编辑后的旧计数）；发球者部分出画仍是证据限制。

## 用户报告边界与掉球切分修正

用户不需要看到检测器置信度、切分过粗或回声等工程诊断；COVERAGE/RALLY_LENGTH/ACTIVITY_MIX 当前规则只保留内部用途，旧报告的这些条目也不交付给球员/教练，不生成系统训练任务。暂时没有经过验证的技术发现时，不编造训练建议。人工创建及教练修改的任务仍保留。

回合切分现结合触球节奏与画面动作中断/重启动作；当前视频发布 v5，96 个粗回合变成 173 个候选回合，首段拆成 5 段。尚非球轨迹级掉球识别，不能宣称整段准确。后端 56 项测试通过；分析库全量测试通过（1 项真实视频环境测试跳过）；前端 build/lint 通过，有既有非阻断警告。
